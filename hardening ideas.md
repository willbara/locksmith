## Cryptographic hardening
- **Hybrid PQC key exchange (X25519 + ML-KEM-768/1024)** — protects against "harvest now, decrypt later," where an attacker stores encrypted data today and decrypts it once quantum computers can break classical ECC.
  - ✅ **Implemented (ML-KEM-768).** New identities are hybrid (`locksmith2…` public keys). A file's key is wrapped with a secret derived from *both* key exchanges, so the X25519 key alone cannot open it. Classical identities can be upgraded from the Keys page, and files encrypted to them before the upgrade still open. ML-KEM-768 rather than 1024: it is the level NIST recommends for general use and what X-Wing and TLS hybrids use; 1024 would add about 400 bytes per key and slot for no practical gain.
- **Constant-time comparisons everywhere** (password checks, MACs, key-commitment checks) — prevents timing side-channels from leaking secrets bit by bit, even if the underlying crypto library is otherwise solid.
  - ✅ **Audited.** Authentication tags are checked inside OpenSSL, and the key commitment already used `hmac.compare_digest`. The remaining local comparisons (password vs. confirmation, share checksums, clipboard contents) now use a constant-time helper, `tools.same_secret`, which also works for non-ASCII text.
- **Hidden/deniable volume mode** — a second password reveals a different (or empty) payload, so you can't be forced to prove hidden data exists.
  - ⏭ **Skipped: too complex to do safely right now.** Real deniability needs a new container format in which *every* file carries a fixed random reserve and an always-present second key slot. Only then do files with and without hidden data look the same in size, header and padding. Any slip gives false assurance, which is worse than not offering it. Deniability also leaks outside the file: recent-file lists, thumbnails, and the app's own "hidden mode" UI. This needs a design of its own (a v3 format) first.
- **Duress password** — opens a decoy vault or wipes the real keys instead of decrypting normally, for coercion scenarios.
  - ⏭ **Skipped.** Wiping doesn't protect against a real adversary, who copies the disk before asking for a password, so the wipe only destroys your own copy. Mistyping it would destroy your data. The decoy half depends on hidden volumes above.

## Hardware-backed security
- **FIDO2/YubiKey as a keyfile option** — hardware-bound secret, can't be copied off disk like a regular keyfile.
  - ⏭ **Deferred: needs hardware to test.** It needs the `fido2` library and the hmac-secret extension. No security key is connected to this machine, and shipping an untested hardware-crypto path is not acceptable. It can be added once a key is available to test with.
- **TPM-backed key sealing** — ties a key to the specific machine's hardware state.
  - ✅ **Implemented for identity keys** (Keys page → chip icon). It uses `systemd-creds` with `host+tpm2`: the key needs this machine's TPM *and* its root-only host key, and is bound to your user account. It works on top of an identity passphrase. There is deliberately no PCR (boot-state) binding, so firmware and Secure Boot updates don't lock you out. Sealing makes you export a portable backup first, since a TPM reset or reinstall makes a sealed key unrecoverable. It is not applied to files: sealing files to one machine would make them unshareable and too easy to lose.

## Operational / anti-forensics
- **Auto-lock on inactivity** — closes the window/wipes in-memory keys if you walk away.
  - ✅ **Implemented** (Settings → Security, default 10 minutes). Locking clears password fields, generated passwords, message text, decrypted previews, open dialogs and any secret on the clipboard, then covers the window. Running encryptions continue. Python can't guarantee freed memory is overwritten, but the process hardening keeps that memory unreadable to other programs.
- **Panic hotkey** — instantly zeroes keys and locks/closes the app on demand.
  - ✅ **Implemented as an in-app shortcut:** Ctrl+Shift+L clears everything, locks and minimizes (Ctrl+L just locks). A *global* hotkey is not possible: Wayland doesn't let apps see keys while unfocused, and the global-shortcuts portal refuses hardened processes.
- **Clipboard auto-clear** — wipes copied passwords/plaintext after a timeout so they don't linger in clipboard history.
  - ✅ **Implemented** (it already existed for passwords). It now also covers decrypted messages and recovered secrets: they are hidden from clipboard managers, cleared after 30 seconds, and cleared on lock and on quit.
- **EXIF/metadata stripping before encryption** — closes a leak separate from the file-name hiding you already have.
  - ✅ **Implemented, opt-in** (Encrypt → Advanced → "Remove photo metadata"). It is lossless for JPEG, PNG and WebP, and works on an allowlist: pixels, colour profile, transparency and animation are kept; EXIF/GPS, XMP, IPTC, comments, C2PA and unknown chunks are dropped. Orientation is preserved. Original files are never modified. For folders it also removes owner names and IDs and original file times from the archive. Other formats are encrypted unchanged, and the app says how many files that applied to.
- **Sandboxed/no-network runtime (seccomp/bwrap profile)** — makes the app technically incapable of phoning home, not just promised to be.
  - ✅ **Implemented with seccomp** on every thread: no internet, raw or other non-local sockets can be created. It also closes the 32-bit syscall and io_uring side doors. Programs Locksmith opens are started by systemd, outside the sandbox. A bwrap filesystem sandbox was not added: Locksmith needs to reach your files wherever they are, so it would restrict nothing meaningful.
- **Screen-capture/recording block on secret-showing windows** — stops screenshots/recordings from grabbing passwords or plaintext previews.
  - ⏭ **Not possible on Linux.** There is no API to mark a window as uncapturable (Windows has `SetWindowDisplayAffinity`, macOS has `sharingType`). On Wayland, capturing other apps already requires a compositor or portal consent prompt; on X11 any program can read the screen. What Locksmith does instead: secrets are masked by default, plaintext and QR codes are shown only on request, and auto-lock clears them.
